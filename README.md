# EvalForge

EvalForge is a reusable AI evaluation framework for scoring batches of prompts and model outputs using a weighted rubric and an LLM-as-judge workflow.

## Why EvalForge

EvalForge helps teams evaluate AI responses consistently, repeatably, and at scale. Instead of manually reviewing prompts one by one, you can define a scoring rubric, feed in batches of prompts, and let the judge model assess each response against the rubric.

It is designed for AI researchers, product teams, QA reviewers, and teams building LLM-powered products who need reliable evaluation without ad hoc scoring workflows.

The system reads input from JSON or Excel, applies a weighted rubric, and produces structured output reports in Excel and HTML. The evaluation policy is separated from the code, so you can change the rubric, criteria, or pass threshold without changing the application logic itself.

## The EvalForge approach

Many evaluation workflows suffer from one or both of these problems:

- scoring is inconsistent across examples
- evaluation logic is tightly coupled to code and hard to maintain

EvalForge solves that by separating the concerns cleanly:

- Input data: prompts, grounded truth, and task context
- Evaluation instructions: scoring rubric and grading policy in Markdown
- Model logic: OpenAI or Azure OpenAI integration
- Output: Excel and HTML reporting for review and reporting

This separation makes the evaluation workflow easier to configure, audit, and reuse across teams and projects.

## Core features

- Reads default input automatically from `input.xlsx`, `input.json`, or `input.csv`
- Supports both JSON and Excel input formats
- Accepts a minimal Excel input format with only `PromptID`, `Prompt`, and `Groundedness Truth`
- Uses a Markdown-based evaluator instruction file to define strict rubric interpretation
- Applies weighted scoring across multiple rubric dimensions
- Uses a threshold-based pass/fail decision, defaulting to 70
- Writes results to an Excel workbook with summary tabs
- Generates an HTML report with charts and score summaries
- Keeps model provider integration separate from evaluation policy

## Evaluation rubric

The default rubric weights are:

- Accuracy: 25%
- Groundedness: 20%
- Completeness: 20%
- Clarity & Structure: 10%
- Handling Ambiguity: 10%
- Hallucination Resistance: 10%
- Formatting / Fidelity: 5%

Weighted score formula:

```text
Overall Score = weighted average of all rubric criteria
```

The pass threshold defaults to 70 unless changed in the instructions file.

## Supported input formats

### 1) JSON input

The JSON format can contain a single record or a `batch` array.

Example:

```json
{
  "criteria": [
    { "name": "Accuracy", "weight": 25 },
    { "name": "Groundedness", "weight": 20 },
    { "name": "Completeness", "weight": 20 },
    { "name": "Clarity & Structure", "weight": 10 },
    { "name": "Handling Ambiguity", "weight": 10 },
    { "name": "Hallucination Resistance", "weight": 10 },
    { "name": "Formatting / Fidelity", "weight": 5 }
  ],
  "batch": [
    {
      "id": "Q1",
      "Prompt": "Explain how to reduce hallucinations in LLMs.",
      "Model Output": "Use grounding, retrieval, fact checking, and careful uncertainty handling.",
      "Groundedness Truth": "Use retrieval, verification, and explicit uncertainty handling."
    }
  ]
}
```

### 2) Excel input

The Excel input can be lightweight. The project supports a minimal format such as:

- PromptID
- Prompt
- Groundedness Truth

This is useful when the rubric scores are meant to be generated by the LLM judge instead of pre-populated in the file.

The evaluator also supports richer Excel files containing rubric columns such as:

- Accuracy
- Groundedness
- Completeness
- Clarity & Structure
- Handling Ambiguity
- Hallucination Resistance
- Formatting / Fidelity
- Weighted Score Formula

The script reads the first spreadsheet automatically.

## How the evaluation works

1. The runner loads the default input file or the file passed in as an argument.
2. It reads the instruction file from `judge-instructions.md`.
3. It builds a strict evaluation prompt for the LLM judge.
4. The model scores each response against the rubric.
5. The system computes the weighted overall score and pass/fail result.
6. It writes the output workbook and HTML summary report.

## Default file behavior

The project looks for a default input file in this order:

1. `input.xlsx`
2. `input.json`
3. `input.csv`

If no file is found, it defaults to `input.xlsx` in the project root. This means you can run the tool without specifying the filename every time.

## Setup

### Step 1: install dependencies

```powershell
npm install
```

### Step 2: create the environment file

```powershell
Copy-Item .env.example .env
```

Then add your credentials to `.env`.

#### OpenAI example

```env
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-4o-mini
```

#### Azure OpenAI example

```env
AZURE_OPENAI_API_KEY=your_azure_openai_key_here
AZURE_OPENAI_ENDPOINT=https://your-resource-name.openai.azure.com/
AZURE_OPENAI_API_VERSION=2024-02-01
AZURE_OPENAI_DEPLOYMENT=your_deployment_name
```

## Run the evaluator

### Run using the default file in the project root

```powershell
npm start
```

### Run with a specific file

```powershell
node llm_judge_agent_starter.js input.xlsx
```

### Run with a custom judge instruction file

```powershell
node llm_judge_agent_starter.js input.xlsx judge-instructions.md
```

## Notes and best practices

- Keep the evaluator instruction file in Markdown so rubric logic stays separate from code.
- Keep the pass threshold high enough to catch low-quality responses while still allowing realistic variance.
- Prefer using a minimal input sheet when you want the judge to generate rubric results dynamically.
- Do not commit your real `.env` file or production API keys.
- If PowerShell blocks npm on your machine during setup, use:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## Quick start for non-technical users

If you just want to use the tool quickly, follow these steps:

1. Open the project folder.
2. Copy `.env.example` to `.env`.
3. Add your OpenAI or Azure OpenAI key.
4. Put your prompts into `input.xlsx` or `input.json`.
5. Run:

```powershell
npm start
```

6. Open the generated `evaluation-output.xlsx` and `evaluation-report.html` files.

You do not need to change code unless you want to customize the rubric or threshold.
